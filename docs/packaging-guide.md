# Packaging Guide

Espress View packages its `src`-layout module and external `assets/icons` with PyInstaller. Build on the same operating system/architecture as the intended executable; PyInstaller is not a cross-compiler.

## Prepare

1. Create and activate a virtual environment as described in the [README](../README.md).
2. Install the app and build tools:

   ```powershell
   python -m pip install -e .
   python -m pip install -r scripts/requirements.txt
   ```

   On macOS/Linux, use the active environment's `python` command in the same way.

## Build

From the repository root:

```powershell
python scripts/build.py build --entry src/espress_view/__main__.py --name espress_view --paths src --add-data assets=assets --collect-data esptool --icon assets/icons/exe-file.ico --metadata metadata.yaml
```

The helper has no application-specific defaults. These options supply Espress View's entry point, name, source import path, icons, esptool package data, and Windows version metadata. It reads the explicitly supplied `metadata.yaml` and generates Windows version information. Output is written to `dist/espress_view.exe` on Windows. Intermediate files are under `build/`. Console mode is intentional because the same executable also runs the esptool worker and captures its standard output/error.

The `.spec` file generated by PyInstaller is placed in `build/`; do not substitute a machine-specific spec containing absolute paths from another checkout.

For generic options, use as a Git submodule, and other application examples, see [scripts/README.md](../scripts/README.md).

## Test the executable

1. Copy the executable to a clean test location or machine without the development environment.
2. Launch it and confirm the GUI opens and its icon appears.
3. Test serial discovery and Monitor against hardware if available.
4. Test the internal worker startup without flashing a device:

   ```powershell
   .\dist\espress_view.exe --esptool-worker --help
   ```

5. Verify the executable metadata/version and test a real flash only with a known-good image and target.

## Clean generated outputs

```powershell
python scripts/build.py clean
```

This removes only the generated `build/` and `dist/` directories. It does not remove logs, archives, source assets, or spec files in the repository root.

## Troubleshooting

- **Missing build module:** activate the intended environment and install `scripts/requirements.txt`.
- **Missing runtime resources:** check that the build command ran from the repository root and `assets/icons` exists.
- **Executable starts then exits:** run it from PowerShell to inspect startup output; check that metadata and PyInstaller dependencies are installed in the build environment.
- **Antivirus warning:** inspect the artifact and build provenance; do not advise users to disable security software globally.
